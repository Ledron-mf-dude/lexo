# Lexo

Тренажер англійських слів з інтервальним повторенням, база знань із граматики та вправи до тем. PWA: працює в браузері, ставиться на телефон як застосунок.

**Стек:** React + TypeScript + Vite, Tailwind, Supabase (Auth + PostgreSQL), GitHub Pages. Свого сервера немає.

## Що всередині

- **Слова:** додавання, теги, пошук, імпорт (Anki, CSV, Excel, JSON), експорт. Транскрипція, запис вимови й частина мови з Wiktionary. Рівень A1–C2 біля слова, фільтр і практика за рівнем. «З тексту»: вставити абзац, побачити знайомі слова й додати нові з чернеткою перекладу.
- **Практика:** алгоритм SM-2, режими: флешкартки, вибір відповіді, введення слова, складання з літер, пропущені літери, слово в реченні, пари, диктант, вимова (розпізнавання мовлення). Комплекс проходить вправи по черзі.
- **Граматика:** 105 статей (`src/content/grammar/*.md`) із пошуком за назвою й темою, фільтрами за рівнем, посиланнями між статтями.
- **Вправи:** 2168 запитань до всіх статей (`src/content/exercises/*.json`) і ще ~360 «Знайди помилку», зібраних із розділів «Типові помилки»; змішані вправи й повторення помилок, результати зберігаються. Тест рівня (A1–B2) і «Ваш маршрут» — теми по порядку з урахуванням помилок. «Тренер письма»: перевірка тексту (LanguageTool), а помилки стають вашими картками.

Контент (статті й вправи) лежить у проєкті як файли. У базі — лише дані користувачів.

## Локальний запуск

```bash
npm install
cp .env.example .env   # вкажіть URL і publishable key з Supabase
npm run dev
```

Відкрийте http://localhost:5173/lexo/.

## Налаштування Supabase (один раз)

1. Створіть проєкт на supabase.com.
2. У **SQL Editor** послідовно виконайте файли з `supabase/migrations/`: `0001_init.sql`, `0002_audio.sql`, `0003_exercise_log.sql`, `0004_word_pronunciation.sql`.
3. **Authentication → Sign In / Providers:** залиште Email, вимкніть **Allow new users to sign up**, якщо застосунок не для відкритої реєстрації.
4. **Authentication → URL Configuration:** у **Site URL** та **Redirect URLs** додайте адресу сайту (`https://<користувач>.github.io/<репозиторій>/`) і `http://localhost:5173/lexo/`. Без цього не працюватиме «Забули пароль?».
5. У **Project Settings → API** візьміть Project URL і Publishable key.

## Додавання користувачів

Реєстрація за замовчуванням вимкнена. Акаунти створює власник:

1. Supabase → **Authentication → Users → Add user → Create new user**.
2. Вкажіть email і тимчасовий пароль, увімкніть **Auto Confirm User**.
3. Передайте людині адресу сайту й пароль. Вона змінює пароль у застосунку: **Акаунт → Змінити пароль**.

Кожен користувач бачить лише свої слова й прогрес (Row Level Security). Статті та вправи спільні. Слова нового користувача починаються з порожнього словника: він може імпортувати власний файл із Anki або файл, експортований іншим користувачем (**Акаунт → Експортувати слова**, потім **Слова → Імпорт**).

## Деплой на GitHub Pages

1. Створіть репозиторій (назва визначає адресу сайту) і запушіть проєкт.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Впишіть URL і publishable key у `.env.production` (файл лежить у репозиторії, це публічні значення).
4. Пуш у `main` запускає збірку та публікацію ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)).

Publishable key публічний за задумом (він потрапляє й у зібраний сайт): дані захищені RLS-політиками, а не секретністю ключа. Ніколи не публікуйте `service_role` ключ і не додавайте його в репозиторій.

**Keep-alive:** [.github/workflows/keep-alive.yml](.github/workflows/keep-alive.yml) кожні 5 днів робить запит до бази, щоб безкоштовний проєкт Supabase не призупинявся. GitHub вимикає заплановані workflows у публічному репозиторії, де 60 днів немає жодних комітів, тож раз на пару місяців зробіть будь-який коміт або запустіть workflow вручну (Actions → Keep Supabase awake → Run workflow).

## Додавання контенту

- **Стаття:** новий файл `src/content/grammar/<slug>.md` із шапкою `title`, `category`, `levels`, `tags`. Посилання на іншу статтю: `«Назва статті»`, воно стане клікабельним автоматично.
- **Вправи:** `src/content/exercises/<slug>.json`, назва файлу збігається зі slug статті. Типи запитань: `choice`, `fill`, `order`. Запитання «Знайди помилку» (`fix`) не пишуться в JSON: вони генеруються з рядків `- ✗ *…* → ✓ *…*` у статтях.

## Обмеження безкоштовного Supabase

- Проєкт **призупиняється після тижня без активності** (його можна відновити в панелі). Від цього захищає keep-alive workflow.
- Вбудована пошта має дуже низький ліміт листів на годину, тому користувачів зручніше створювати вручну, як описано вище.
